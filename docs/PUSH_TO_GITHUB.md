## 2. Commands to answer (2) and (3) right now

Paste-and-run — all read-only, all scoped to the workspace, none can prompt:

```powershell
# (2) versions + auth
git --version
gh --version
$env:GH_PROMPT_DISABLED = "1"; gh auth status --hostname github.com

# (3) does the repo exist, and is it empty?
$env:GIT_TERMINAL_PROMPT = "0"
git -c credential.helper= ls-remote --heads --tags https://github.com/arshad-88/FS
# empty output + exit 0  -> repo exists and is EMPTY
# "could not read Username"/"Authentication failed" -> private or non-existent
```

The `ls-remote` above can still stall on a bad network. Guard it:

```powershell
$env:GIT_TERMINAL_PROMPT = "0"
$j = Start-Job { git -c credential.helper= ls-remote --heads --tags https://github.com/arshad-88/FS }
if (Wait-Job $j -Timeout 20) { Receive-Job $j } else { "TIMEOUT after 20s"; Stop-Job $j }
Remove-Job $j -Force
```

Or just run the script, which does all of §2 and §3 in one pass:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\preflight-push.ps1
```

### Reading the emptiness answer

| Observed | Meaning | Next step |
| --- | --- | --- |
| `ls-remote` exit 0, **no lines** | exists, **empty** | first push is a clean fast-forward |
| `ls-remote` exit 0, refs listed | exists, **has commits** | see §6 (merge vs. force) |
| `could not read Username` / `terminal prompts disabled` | private repo, or wrong slug | authenticate, then `gh repo view arshad-88/FS` |
| `Repository not found` / exit 128 | does not exist | create it (§3) |

`gh` gives an authoritative answer when authenticated:

```powershell

gh api repos/arshad-88/FS --template '{{.size}} {{.default_branch}} {{.private}}{{"\n"}}'
```

`"isEmpty": true` (or `size 0`) is the definitive signal.

## 3. Create the remote (only if it does not exist)

Create it **empty** — no README, no `.gitignore`, no licence. A GitHub-created
README makes the first push a non-fast-forward and forces a merge decision
(§6) that you can simply avoid.

```powershell
gh auth login --hostname github.com --git-protocol https --web
gh auth setup-git --hostname github.com          # wires git's credential helper
gh repo create arshad-88/FS --private --description "FamilyShield - personal safety app"
```

Flip to `--public` deliberately, after adding a `LICENSE`.

## 4. Why the new `.gitignore` matters

Without it, the first `git add -A` would commit:

* `server/data/.token-secret` — the HMAC key that signs every bearer token;
* `server/data/familyshield.db*` — a live database with real phone numbers;
* `keystore/` — the APK signing private key;
* `.deps/firebase/` — 75 vendored jars, regenerable via `tools/fetch_firebase_deps.py`;
* `Microsoft/` — a stray PowerShell cache, not project content.

The rules are written so `server/.env.example` stays tracked while `server/.env`
and real secrets never are. `keystore/` is safe to ignore because
`tools/build_apk.py` regenerates `keystore/debug.keystore` on first run
(`-storepass android`, debug-grade key only).

## 5. The actual push

```powershell
# 1. read-only rehearsal - prints every command, changes nothing
powershell -NoProfile -ExecutionPolicy Bypass -File tools\push-to-github.ps1

# 2. do it
powershell -NoProfile -ExecutionPolicy Bypass -File tools\push-to-github.ps1 `
    -UserName "Mohd Arshad Ali" -UserEmail "you@example.com" -Execute
```

What `-Execute` performs, in order:

1. `git init -b main` (falls back to `init` + `symbolic-ref` on git < 2.28);
2. `git config core.longpaths true` — required for deep `.deps` paths on Windows;
3. repo-local `user.name` / `user.email` if globally unset;
4. `git add --all`, then a **blocking audit** of the staged list: any
   `server/data/`, `keystore/`, `.env`, `.token-secret`, `service-account*.json`,
   `.deps/`, `node_modules/`, `Microsoft/` or >95 MB file aborts the run;
5. `git commit -m "Initial commit: FamilyShield"`;
6. `git remote add origin https://github.com/arshad-88/FS` (or `set-url` if it
   points somewhere else);
7. `git ls-remote --heads origin` to see whether `main` already exists;
8. `git push --set-upstream origin HEAD:refs/heads/main`.

Equivalent manual sequence, if you prefer typing it:

```powershell
$ws = "C:\Users\Mohd Arshad Ali\AppData\Local\Tenzy\Projects\FamilyShield33"
git -C $ws -c safe.directory=$ws init -b main
git -C $ws -c safe.directory=$ws config core.longpaths true
git -C $ws -c safe.directory=$ws add --all
git -C $ws -c safe.directory=$ws status --porcelain          # eyeball this
git -C $ws -c safe.directory=$ws commit -m "Initial commit: FamilyShield"
git -C $ws -c safe.directory=$ws remote add origin https://github.com/arshad-88/FS
git -C $ws -c safe.directory=$ws push -u origin HEAD:refs/heads/main
```

**Always keep `git -C $ws`.** A repo exists in the home directory whose ownership
git considers dubious; running bare `git` from a home-relative cwd is what raises
`detected dubious ownership in repository`. `-C` plus `safe.directory` pins every
command to the workspace and bypasses the issue without weakening
`safe.directory` globally.

## 6. If the remote already has commits

`gh repo create` without `--add-readme` gives an empty repo, so this should not
happen. If it does (README/licence auto-added), pick one:

```powershell
# keep remote history, replay local work on top
git -C $ws fetch origin
git -C $ws rebase origin/main

# or keep both (creates a merge commit; expect .gitignore/README conflicts)
git -C $ws fetch origin
git -C $ws merge --allow-unrelated-histories origin/main

# or declare the remote content disposable
git -C $ws push --force-with-lease -u origin HEAD:refs/heads/main
```

Prefer `--force-with-lease` over `--force`: it refuses if someone else pushed
since your last fetch. Never `--force` a shared branch.

## 7. Windows failure modes and fixes

| Symptom | Cause | Fix |
| --- | --- | --- |
| `fatal: detected dubious ownership in repository at 'C:/Users/...'` | git resolved the **home** repo, not the workspace | always `git -C "$ws"`; or `git config --global --add safe.directory "$ws"` |
| push hangs forever, no prompt | `GIT_TERMINAL_PROMPT` unset + no stored credential | scripts set `GIT_TERMINAL_PROMPT=0`, `GCM_INTERACTIVE=never`; then `gh auth login` + `gh auth setup-git` |
| `remote: Support for password authentication was removed` | used an account password | use a PAT or `gh auth login`; never the password |
| `fatal: could not read Username for 'https://github.com'` | no credential helper wired | `gh auth setup-git --hostname github.com` |
| `error: RPC failed; curl 56 ... schannel` / `curl 92 HTTP/2 stream` | flaky TLS / large first push on Windows schannel | `git config --global http.postBuffer 524288000`; `git config --global http.version HTTP/1.1`; retry |
| `Filename too long` | path >260 chars under `.deps` | `git config core.longpaths true` (script sets it) and enable Windows LongPathsEnabled |
| hundreds of phantom modified files after clone | CRLF vs LF | `.gitattributes` now pins `eol=lf`; set `core.autocrlf=input` |
| `src refspec main does not match any` | commit failed (no identity) or branch named `master` | set `user.name`/`user.email`; push `HEAD:refs/heads/main` explicitly |
| `! [rejected] main -> main (fetch first)` | remote non-empty | §6 |
| `GH_TOKEN`/`GITHUB_TOKEN` exported in shell shadows `gh auth` | env token wins over keyring | `Remove-Item Env:GH_TOKEN` before `gh auth status` |
| push succeeds but `.deps`, `keystore`, `server/data` are on GitHub | `.gitignore` added after `git add` | `git -C $ws rm -r --cached keystore server/data .deps Microsoft; git -C $ws commit -m "Untrack generated paths"` — and if a secret was already pushed, **rotate it** |
